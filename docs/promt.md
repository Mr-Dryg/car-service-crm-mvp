## БИЗНЕС-КОНТЕКСТ И СЦЕНАРИИ ИСПОЛЬЗОВАНИЯ (БИЗНЕС-ЛОГИКА)

### Описание бизнеса

Система автоматизирует сеть автосервисов (СТО). Главная цель проекта — **минимизировать нагрузку на телефонную линию менеджера** и дать клиенту прозрачный трекинг ремонта, исключив из цепочки сторонние мессенджеры. Всё взаимодействие происходит внутри единого веб-приложения. 

### Ключевые бизнес-сценарии (User Stories)

#### Сценарий 1: Экспресс-запись и бесшовная регистрация

* **Проблема:** Клиенты не любят проходить долгую регистрацию (подтверждение почты, ввод кодов) ради одной заявки.
* **Бизнес-логика для AI:** Когда человек впервые заходит на сайт, он видит простую форму записи на ремонт. Система берет его телефон, имя и введенный тут же пароль — и **одновременно** создает и заявку на ремонт, и полноценный Личный кабинет. Клиент мгновенно авторизуется и попадает на экран отслеживания своей машины.

#### Сценарий 2: Интеллектуальный календарь (Защита от овербукинга)

* **Проблема:** Менеджер тратит много времени, сопоставляя новые заявки с реальной загрузкой боксов (подъемников), из-за чего возникают очереди или простои.
* **Бизнес-логика для AI:** Когда менеджер открывает новую заявку на условное «25 октября», система делает агрегирующий запрос в БД. Она считает, сколько машин уже записано на этот день. Менеджер видит не просто сухой список, а **цветовую шкалу дня**. Если шкала красная (СТО перегружено), менеджер сразу понимает, что при звонке клиенту нужно предложить другое время или другой филиал.

#### Сценарий 3: Разгрузка телефона при выдаче («Я в пути»)

* **Проблема:** Когда машина готова, менеджер обязан позвонить клиенту. Клиент часто не берет трубку, менеджер звонит снова, тратится рабочее время.
* **Бизнес-логика для AI:** Как только ремонт завершен, статус меняется на ready, и клиенту уходит SMS со ссылкой. Клиент заходит в личный кабинет и нажимает кнопку **«Подтверждаю, скоро буду»**. В этот момент у менеджера на экране мгновенно (через WebSocket) загорается зеленый статус: *«Клиент едет, звонить не нужно»*. Менеджер спокойно готовит документы к выдаче, не совершая лишних звонков.

#### Сценарий 4: Контроль «отказников» (Красная зона отмен)

* **Проблема:** Если клиент передумал, он просто не приезжает, и бокс простаивает, теряя деньги. Либо он отменяет запись, а менеджер замечает это слишком поздно.
* **Бизнес-логика для AI:** Клиенту дана возможность отменить запись в один клик в ЛК (пока машину не загнали в бокс). Но система не удаляет её молча. Она переводит её в статус canceled и выбрасывает в **«Красную зону»** на экране менеджера со звуковым алертом. Менеджер должен немедленно увидеть эту отмену, перезвонить клиенту («Что случилось? Давайте перенесем на другой день?»). Если клиент окончательно отказался, менеджер нажимает «Удалить», и слот времени освобождается для других. Если договорились о переносе — менеджер нажимает «Восстановить» и меняет дату прямо в карточке.

## ТЗ: Веб-платформа автоматизации СТО (CRM + Личный кабинет)

### 1. ОБЩИЕ ТРЕБОВАНИЯ И СТЕК

* **Backend:** Go (Golang). Разрешается использовать стандартную библиотеку или фреймворки (например, Gin, Fiber, Chi). Код должен быть структурирован (Clean Architecture или Layered Architecture).
* **Frontend:** На усмотрение AI-агента (SPA/SSR: React, Vue, Svelte или чистый HTML/JS с TailwindCSS для компактности). Обязательное требование: адаптивная верстка (Mobile First).
* **База данных:** PostgreSQL. Все связи, внешние ключи и индексы на часто запрашиваемые поля (номер телефона, статус, дата записи) должны быть явно определены.
* **Авторизация:** JWT-токены (хранение в HttpOnly Cookies или LocalStorage).
* **Уведомления:** Заглушки (Mock-функции / логгирование в консоль) для отправки SMS/Email, готовые к интеграции реального API.

### 2. СТРУКТУРА БАЗЫ ДАННЫХ (PostgreSQL)

sql

-- Роли пользователей
CREATE TYPE user_role AS ENUM ('client', 'manager', 'superadmin');

-- Статусы заказа
CREATE TYPE order_status AS ENUM ('new', 'confirmed', 'canceled', 'in_progress', 'ready', 'completed');

-- Филиалы (СТО)
CREATE TABLE branches (
    id SERIAL PRIMARY KEY,
    address VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Пользователи (Общая таблица для всех ролей)
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    phone VARCHAR(20) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    name VARCHAR(100) NOT NULL,
    role user_role NOT NULL DEFAULT 'client',
    branch_id INT REFERENCES branches(id) ON DELETE SET NULL, -- Только для менеджеров
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Заявки / Заказы на ремонт
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    client_id INT REFERENCES users(id) ON DELETE CASCADE,
    branch_id INT REFERENCES branches(id) ON DELETE RESTRICT,
    car_number VARCHAR(20) NOT NULL,
    service_type VARCHAR(100) NOT NULL,
    preferred_date DATE NOT NULL,
    preferred_time TIME NOT NULL,
    comment TEXT,
    status order_status NOT NULL DEFAULT 'new',
    is_client_en_route BOOLEAN DEFAULT FALSE, -- Флаг "Подтверждаю, скоро буду"
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

### 3. СПЕЦИФИКАЦИЯ API (REST)

### Публичные эндпоинты (Без авторизации)

* GET /api/branches — Получить список всех филиалов (для выпадающего списка в форме).
* POST /api/orders/public — Создание первой заявки + автоматическая регистрация клиента. 

  * *Payload:* { phone, password, name, branch_id, car_number, service_type, preferred_date, preferred_time, comment }
* POST /api/auth/login — Авторизация (вход по телефону и паролю). Возвращает JWT и роль пользователя.

### Эндпоинты Клиента (Требуется JWT, роль client)

* GET /api/client/orders — Получить список текущих и прошлых заказов авторизованного клиента.
* POST /api/client/orders/:id/cancel — Отменить заказ (разрешено только если статус заказа new или confirmed). Переводит в canceled.
* POST /api/client/orders/:id/en-route — Нажатие кнопки «Подтверждаю, скоро буду, не звоните» (разрешено только для статуса ready). Устанавливает is_client_en_route = true.

### Эндпоинты Менеджера (Требуется JWT, роль manager)

*Все запросы менеджера автоматически фильтруются на бэкенде по его branch_id.* 

* GET /api/manager/orders — Получить список всех заказов филиала (с фильтрацией по статусу, дате или поиском по имени/телефону).
* GET /api/manager/orders/today — План на сегодня (быстрая выборка заказов на текущую дату).
* GET /api/manager/slots?date=YYYY-MM-DD — Данные для Интеллектуального календаря (возвращает загруженность филиала на дату для расчета цветовой шкалы).
* PATCH /api/manager/orders/:id/status — Смена статуса заказа. 

  * *Payload:* { status: "confirmed" | "in_progress" | "ready" | "completed" }
  * *Логика:* При переходе в ready триггерится отправка SMS-уведомления клиенту.
* DELETE /api/manager/orders/:id — Окончательное удаление отмененного клиентом заказа из расписания (освобождение слота).

### Эндпоинты Суперадмина (Требуется JWT, роль superadmin)

* GET /api/admin/dashboard — Сводная информация по загруженности всех филиалов.
* POST /api/admin/branches — Создать новый филиал СТО.
* POST /api/admin/managers — Создать аккаунт менеджера и привязать к конкретному branch_id.

### 4. БИЗНЕС-ЛОГИКА И ФУНКЦИОНАЛ ИНТЕРФЕЙСОВ

### Интерфейс Клиента

1. **Форма заявки:** Простая страница. Поля ввода + поле для создания пароля. После отправки — автоматический редирект в созданный Личный кабинет.
2. **Личный кабинет:** Простой дашборд. Список карточек авто. Рядом с карточкой в статусе ready отображается яркая кнопка «Подтверждаю, скоро буду». Доступна кнопка «Отменить», если ремонт еще не начался.

### Интерфейс Менеджера (Адаптивный CRM)

1. **Календарь и Шкала:** При клике на новую заявку отображается таймлайн дня (09:00 - 21:00). На основе количества заказов на это время бэкенд отдает степень загрузки. Фронтенд красит шкалу: до 30% — зеленый, 30-70% — желтый, более 70% — красный.
2. **Мгновенные Web Push/Звук:** Использовать WebSockets (или Server-Sent Events / Long Polling на выбор агента) для отправки менеджеру события "Новая заявка" или "Запись отменена клиентом". При событии проигрывать системный звук уведомления и обновлять список без перезагрузки страницы.
3. **Красная зона отмен:** Вверху или на видном боковом блоке интерфейса менеджера находится секция «Отменено клиентами» (выделена красным цветом). Оттуда менеджер совершает звонки для разбора отмен и нажимает либо «Удалить», либо «Восстановить» (с возможностью открыть модальное окно и поменять дату/время).

### Жизненный цикл заказа (status):

new (с сайта) ➔ confirmed (менеджер подтвердил) ➔ in_progress (чинят) ➔ ready (готово, ушло SMS) ➔ completed (забрали, закрыто).
*Из статусов new и confirmed клиент может перевести заказ в canceled.* 

### 5. КРИТЕРИИ ПРИЕМКИ ДЛЯ AI-АГЕНТА

1. Бэкенд успешно запускается, компилируется без ошибок и слушает порт.
2. Создана миграция базы данных или автоматическая инициализация таблиц (AutoMigrate) при старте приложения Go.
3. Фронтенд корректно отображается как на экранах смартфонов (ширина от 360px), так и на десктопе.
4. Веб-сокеты или SSE стабильно доставляют уведомления менеджеру в реальном времени при действиях клиента.
5. Пароли в базе данных хранятся строго в захешированном виде (bcrypt).
