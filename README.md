# CRM сети автосервисов (СТО) — MVP

Веб-платформа для сети автосервисов: экспресс-запись клиента с бесшовной регистрацией,
интеллектуальный календарь загрузки филиала, мгновенные уведомления менеджеру через WebSocket
и «красная зона» клиентских отмен.

## Возможности

| Сценарий | Реализация |
|---|---|
| Экспресс-запись и бесшовная регистрация | `POST /api/orders/public` создаёт аккаунт клиента и заявку одним запросом, клиент сразу авторизован |
| Интеллектуальный календарь | `GET /api/manager/slots` отдаёт почасовую загрузку филиала с цветовой шкалой (зелёный ≤30%, жёлтый 30–70%, красный >70%) |
| Разгрузка телефона («Я в пути») | Кнопка «Подтверждаю, скоро буду» → WebSocket-событие менеджеру + зелёный статус «звонить не нужно» |
| Контроль отказников | Отмена клиентом попадает в «красную зону» менеджера со звуковым алертом; кнопки «Удалить» и «Восстановить» с переносом даты |

## Стек

- **Backend:** Go 1.26, `chi` (HTTP), `pgx/v5` (PostgreSQL), `gorilla/websocket`, `golang-jwt/jwt/v5`, `bcrypt`
- **Frontend:** Vue 3 + Vite + TailwindCSS, встраивается в бинарь через `go:embed`
- **БД:** PostgreSQL 16, автоматическая инициализация схемы при старте

## Структура проекта

```
crm/
├── backend/
│   ├── cmd/server/          # Точка входа, демо-данные
│   └── internal/
│       ├── config/          # Конфигурация из переменных окружения
│       ├── domain/          # Доменные сущности: User, Order, Branch, статусы
│       ├── store/           # Доступ к данным, миграции, репозитории
│       ├── service/         # Бизнес-логика: auth, заказы, слоты, админка
│       ├── httpapi/         # Роутинг, middleware, обработчики
│       ├── realtime/        # WebSocket-хаб событий для менеджеров
│       └── webui/           # Встроенный SPA (go:embed)
└── frontend/                # Исходники SPA (Vue 3 + Tailwind)
```

Архитектура — слоистая: `httpapi → service → store → PostgreSQL`,
с доменными моделями в `domain` и сквозными событиями в `realtime`.

## Запуск

### 1. База данных

```bash
docker run -d --name sto-crm-db -p 5432:5432 \
  -e POSTGRES_USER=user -e POSTGRES_PASSWORD=password -e POSTGRES_DB=sto_crm \
  postgres:16
```

### 2. Сборка фронтенда

Фронтенд собирается прямо в каталог `embed` бинаря Go:

```bash
cd frontend
npm install
npm run build          # результат попадёт в backend/internal/webui/dist
```

### 3. Сборка и запуск сервера

```bash
cd backend
go build -o ../bin/sto-crm.exe ./cmd/server   # Windows
# go build -o ../bin/sto-crm ./cmd/server      # Linux/macOS

cd ..
DATABASE_URL="postgres://user:password@localhost:5432/sto_crm?sslmode=disable" \
JWT_SECRET="your-secret-key" \
./bin/sto-crm.exe
```

Сервер слушает `http://localhost:8080` и сам отдаёт фронтенд.

### Режим разработки

```bash
# Терминал 1 — API
cd backend && go run ./cmd/server

# Терминал 2 — фронтенд с hot-reload (проксирует /api и /ws на :8080)
cd frontend && npm run dev
```

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт HTTP-сервера |
| `DATABASE_URL` | `postgres://user:password@localhost:5432/sto_crm?sslmode=disable` | Строка подключения к PostgreSQL |
| `JWT_SECRET` | `change-me-in-production-secret-key` | Секрет подписи JWT (обязательно заменить в продакшене) |
| `JWT_TTL` | `720h` | Время жизни токена |
| `SLOT_CAPACITY` | `4` | Количество параллельных боксов (подъёмников) на филиале — база расчёта загрузки |
| `WORK_DAY_START` / `WORK_DAY_END` | `09:00` / `21:00` | Границы рабочего дня для таймлайна |
| `SEED_DEMO_DATA` | `true` | Создание демо-данных при пустой БД |
| `SUPERADMIN_PHONE` / `SUPERADMIN_PASSWORD` | `+79000000001` / `admin12345` | Учётная запись суперадмина |

## API

### Публичные

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/branches` | Список филиалов для выпадающего списка |
| `POST` | `/api/orders/public` | Экспресс-заявка + регистрация клиента |
| `POST` | `/api/auth/login` | Вход по телефону и паролю → JWT |

### Клиент (роль `client`)

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/client/orders` | Текущие и прошлые заказы |
| `POST` | `/api/client/orders/:id/cancel` | Отмена (только из `new`/`confirmed`) |
| `POST` | `/api/client/orders/:id/en-route` | «Подтверждаю, скоро буду» (только из `ready`) |

### Менеджер (роль `manager`, данные фильтруются по `branch_id`)

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/manager/orders` | Заказы филиала (`?status=`, `?date=`, `?search=`, `?canceled=1`) |
| `GET` | `/api/manager/orders/today` | План на сегодня |
| `GET` | `/api/manager/slots?date=YYYY-MM-DD` | Данные интеллектуального календаря |
| `PATCH` | `/api/manager/orders/:id/status` | Смена статуса |
| `POST` | `/api/manager/orders/:id/restore` | Восстановление отмены с переносом даты/времени |
| `DELETE` | `/api/manager/orders/:id` | Окончательное удаление отменённого заказа |
| `GET` | `/api/manager/ws` | WebSocket-поток событий (токен — в query: `?token=`) |

### Суперадмин (роль `superadmin`)

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/admin/dashboard` | Сводка по загруженности всех филиалов |
| `POST` | `/api/admin/branches` | Создание филиала |
| `POST` | `/api/admin/managers` | Создание менеджера с привязкой к филиалу |

### Формат ошибок

```json
{
  "error": "Недопустимый переход: Подтверждена → Завершена",
  "fields": { "status": "недопустимый переход" }
}
```

| Код | Значение |
|---|---|
| `401` | Не авторизован / неверные учётные данные |
| `403` | Недостаточно прав / чужой филиал / чужой заказ |
| `422` | Ошибка валидации или недопустимый переход статуса |
| `404` | Объект не найден |

## Жизненный цикл заказа

```
new → confirmed → in_progress → ready → completed
 └────────┴────────→ canceled ────────┘
```

- Отменить может клиент, пока статус `new` или `confirmed`.
- Переход в `ready` отправляет SMS клиенту со ссылкой на кабинет.
- Клиент может нажать «Подтверждаю, скоро буду» только в статусе `ready` —
  менеджер мгновенно видит зелёный статус и не звонит.
- Отмена клиентом попадает в «красную зону» менеджера с звуковым алертом.

## Безопасность

- Пароли хранятся только в виде bcrypt-хешей (`$2a$10$...`).
- JWT подписывается HMAC-SHA256, доступ разграничен по ролям через middleware.
- Все запросы менеджера автоматически ограничены его `branch_id` — записи другого филиала недоступны.
- Клиент не может отменять или подтверждать чужие заказы.
- SQL-параметризован: инъекции невозможны.

## Уведомления

Отправка SMS/Email реализована заглушкой `LogNotifier` — сообщения пишутся в консоль
с префиксом `[SMS]`/`[EMAIL]`. Для подключения реального шлюза достаточно реализовать
интерфейс `service.Notifier` и заменить его в `cmd/server/main.go`.
